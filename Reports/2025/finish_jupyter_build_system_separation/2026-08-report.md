## Summary of Work Completed

This time:
- We released v1.1 and v1.2 along with three patch releases (https://github.com/jupyterlab/jupyter-builder/blob/main/CHANGELOG.md#122)
- We made multiple improvements to facilitate the transition, fixing issues reported by the community of extension developers and packagers:
  - thanks to the jupyter-builder switch we were able to fix a severe regression in the build system promptly: the rspack 2.0 transition that happened in parallel to the jupyter-builder work inadvertently switched to Module Federation v2, subtly changing the semantics of requirement specification; this broke extensions that depended on older versions of packages that were not marked as singletons (e.g. `@jupyterlab/docprovider`). We quickly released a new minor version switching back to MF v1. Before the jupyter-builder introduction, this switch would have required a JupyterLab release and longer deliberation on the impact on all consumers, but thanks to this work we were able to roll out a fix within 24 hours of the report, because we can now make major changes to the build system and downstreams can defer upgrades as they see fit (https://github.com/jupyterlab/jupyter-builder/pull/155). We discovered the root cause after debugging an issue reported by `@jupyter/chat` maintainers
  - we improved error messages shown for users who try to compile with an unsupported Node.js version (https://github.com/jupyterlab/jupyter-builder/pull/135) - based on feedback from an extension developer
  - we improved performance of package discovery (https://github.com/jupyterlab/jupyter-builder/pull/138) - addressing feedback from a UC Berkeley extension developer
  - we improved support for incomplete version specifiers for legacy `@jupyterlab/builder` shim (https://github.com/jupyterlab/jupyter-builder/pull/159) - after debugging an issue reported by the `jupytergis` maintainers
  - we improved fallback resolution (https://github.com/jupyterlab/jupyter-builder/pull/153) - after debugging an issue encountered by a developer at the Space Telescope Science Institute
  - we fixed Windows support which regressed after dependency updates contributed by the community (https://github.com/jupyterlab/jupyter-builder/pull/164) - based on feedback from two extension developers using Windows; this also led to fixing a pre-existing issue preventing watch compilation from working in editable builds on Windows
  - we fixed silent fallback when a version specifier could not be matched (https://github.com/jupyterlab/jupyter-builder/pull/121)
- We reviewed the pull requests contributed by packagers and extension developers:
  - updating multiple dependencies (https://github.com/jupyterlab/jupyter-builder/pull/130, https://github.com/jupyterlab/jupyter-builder/pull/132, https://github.com/jupyterlab/jupyter-builder/pull/134, https://github.com/jupyterlab/jupyter-builder/pull/136)
  - improving symlink resolution (https://github.com/jupyterlab/jupyter-builder/pull/149)
  - adding typing marker (https://github.com/jupyterlab/jupyter-builder/pull/147)
  - updating licence metadata (https://github.com/jupyterlab/jupyter-builder/pull/168)
- We worked on reducing the maintenance cost to make it easy to self-sustain beyond the time of this funded work:
   - adding linting to ensure minimum and sufficient dependency coverage (https://github.com/jupyterlab/jupyter-builder/pull/150)
   - improving coverage reporting and speeding up the tests (https://github.com/jupyterlab/jupyter-builder/pull/144)
   - fixing flaky tests (https://github.com/jupyterlab/jupyter-builder/pull/151)

## Deliverables/Milestones

We continue working on the final metric:

> Metric 3. Feedback sought from maintainers, packagers and extension developers confirms that they are willing to use the new builder package and they are satisfied by migration guidelines with the advantages of the solution outweighing the cost of migration (which we will aim to minimize by clear and helpful documentation).

At this point we see a clear indication of the community using and benefiting from the `jupyter-builder` package. We see the packagers trying to nudge the ecosystem towards adoption (e.g. https://github.com/jupyter/nbdime/pull/820), and we continue working on addressing any issues they may encounter.
