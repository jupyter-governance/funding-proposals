## Summary of Work Completed

New rules were added to the ESLint plugin and enabled downstream; existing rules were improved:
- new `jupyter/no-pageconfig-base-url` https://github.com/jupyterlab/eslint-plugin/pull/68
- new `jupyter/no-schema-enum` rule https://github.com/jupyterlab/eslint-plugin/pull/55, https://github.com/jupyterlab/eslint-plugin/pull/60, https://github.com/jupyterlab/eslint-plugin/pull/58
- new `jupyter/require-soft-assertions-before-snapshots` rule https://github.com/jupyterlab/eslint-plugin/pull/53
- improved `jupyter/plugin-activation-args` rule https://github.com/jupyterlab/eslint-plugin/pull/64, https://github.com/jupyterlab/eslint-plugin/pull/54, https://github.com/jupyterlab/eslint-plugin/pull/56
- improved `jupyter/no-untranslated-string` https://github.com/jupyterlab/eslint-plugin/pull/49

We performed necessary maintenance and improved the documentation
- fixing release workflow https://github.com/jupyterlab/eslint-plugin/issues/46
- add CONTRIBUTING.md https://github.com/jupyterlab/eslint-plugin/pull/67

The existing linter rules in JupyterLab were tightened and new ones were added:
- spell checking for documentation https://github.com/jupyterlab/jupyterlab/pull/18398
- regular expression linting https://github.com/jupyterlab/jupyterlab/pull/18908
- rule to forbid serial mode in regression testing https://github.com/jupyterlab/jupyterlab/pull/18838
- GitHub Actions security linter  https://github.com/jupyterlab/jupyterlab/pull/18898
- adopted shell script and documentation linter https://github.com/jupyterlab/jupyterlab/pull/18858
- forbid explicit `any` https://github.com/jupyterlab/jupyterlab/pull/18847
- and progressively remove it from the codebase https://github.com/jupyterlab/jupyterlab/pull/18869
- enforce that certain CSS rules use variables https://github.com/jupyterlab/jupyterlab/pull/18614

The blog post describing the ESLint plugin was published: https://blog.jupyter.org/catching-jupyter-specific-bugs-before-ci-does-announcing-jupyter-eslint-plugin-fc65ae414630

The ESLint plugin was included in the latest version of JupyterLab extension-template (https://github.com/jupyterlab/extension-template/pull/141, https://github.com/jupyterlab/extension-template/releases/tag/v4.6.0)

We started adopting the eslint plugin in official Jupyter extensions:
- https://github.com/jupyterlab/jupyter-collaboration/pull/602
- https://github.com/jupyterlab/jupyterlab-git/pull/1491

## Budget Update

As of 23rd June 2026 we used 8,591 USD out of 17,496 USD budget.

20% of the budget was used to support the visual testing improvements,
with the end-goal of preventing future regressions in the test suite reliability
by codifying all the best practices developed throughout the work on the [proposal focused on the visual regression tests](https://jupyter-governance.github.io/funding-proposals/projects/2025/improve-visual-regression-testing#june-2026).


## Next Steps

- Tightening of select rules in extension-template and Notebook repositories based on lessons from the adoption of stricter rules in JupyterLab, accounting for distinct needs of these two repositories
- Adding linting rules for galata visual testing to prevent flaky tests from being committed in the first place
- Further improve the ESLint plugin, based on any community feedback received

Beyond these, we intend to spend the remainder of the budget on ensuring no flaky tests are present, enabling easy validation of the efficacy of the linting rules preventing flakiness of UI tests.
